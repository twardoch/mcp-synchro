Specification: Upgrading mcp-synchro for the May 2026 Ecosystem
1. Executive Summary & Context Bounding
As of May 2026, the ecosystem of AI developer interfaces and terminal tools has evolved significantly. Google has officially released Antigravity 2.0 as a dedicated, standalone desktop application optimized for agentic operations, alongside the specialized developer platform Antigravity IDE. Simultaneously, the terminal footprint has crystallized around the Antigravity CLI (agy), which replaces the sunsetted Gemini CLI framework.
Furthermore, there is an ongoing convergence and subtle friction in remote server specifications under the Model Context Protocol (MCP)—most notably the field discrepancy between standard implementations using url versus Google/Windsurf ecosystems relying on serverUrl or httpUrl.
This specification acts as the definitive roadmap to transition mcp-synchro from its current state to a fully robust package that natively registers, manages, and maps configurations across all variants of the Antigravity product suite and its localized field quirks.
2. Structural Analysis of the Antigravity Ecosystem (May 2026)
To effectively sync configs, mcp-synchro must catalog three separate configurations under the Antigravity architecture, each with dedicated paths and environment layouts.

3. Remote Server Field Resolution (url vs. serverUrl)
3.1 Domain Conflict
The canonical MCP format originated by Anthropic utilizes url under the Server-Sent Events (SSE) transport paradigm. Conversely, the Antigravity lineup and Windsurf have formalized Streamable HTTP Transport, utilizing the field serverUrl to point to secure remote agent cloud environments or hosted GCP endpoints.
If an agent config maps a remote server using a raw url string key to an Antigravity module, the client fails silently.
3.2 Normalization Engine Rules
Our source of truth (mcp.json) must serve as a perfect lossless superset. To avoid stripping vendor-specific fields when running pipeline synchronization:
1. On Pull: If serverUrl or httpUrl is discovered in a client configuration, extract it and preserve it alongside standard url fields within the McpServer Pydantic schema.
2. On Push: The writing engine must inspect the AgentDef properties. If the target agent belongs to the Antigravity or Windsurf cluster, mcp-synchro must explicitly inject the value of the master url into the target field name (serverUrl) if it is not already explicitly declared.

def _normalize_antigravity_fields(server_dict: dict[str, Any]) -> dict[str, Any]:
    """Ensures remote servers explicitly resolve standard url keys to serverUrl to map to Antigravity core protocols safely."""
    mutated = dict(server_dict)
    
    # Fallback assignment for Streamable HTTP targets
    if "url" in mutated and mutated["url"] and not mutated.get("serverUrl"):
        mutated["serverUrl"] = mutated["url"]
        
    return mutated

def update_mcp_servers(
    data: dict[str, Any],
    mcp_config: McpServersConfig,
    agent: AgentDef,
) -> dict[str, Any]:
    result = data.copy()

    if agent.is_toml:
        new_servers = mcp_config.to_toml_dict()
    else:
        new_servers = mcp_config.to_dict()

    # Intercept targets belonging to the Antigravity space
    if "antigravity" in agent.id:
        new_servers = {
            name: _normalize_antigravity_fields(cfg) if isinstance(cfg, dict) else cfg
            for name, cfg in new_servers.items()
        }

    # Rest of the pipeline continues cleanly...
    if agent.command_as_array:
        new_servers = {
            name: _to_opencode_server(cfg) if isinstance(cfg, dict) else cfg
            for name, cfg in new_servers.items()
        }

    if agent.server_format == "array":
        new_servers_data = _dict_to_array(new_servers)
    else:
        new_servers_data = new_servers

    if agent.mcp_wrapper_key:
        if agent.mcp_wrapper_key not in result:
            result[agent.mcp_wrapper_key] = {}
        result[agent.mcp_wrapper_key][agent.mcp_key] = new_servers_data
    else:
        result[agent.mcp_key] = new_servers_data

    return result

# mcp-synchro — May 2026 Update Spec

**Author:** Spec for Adam Twardoch / Fontlab Ltd
**Target version:** `mcp-synchro` 0.4.x (post-March 2026 baseline)
**Status:** Draft — actionable engineering spec
**Scope:** Incorporate Antigravity 2.0 (Desktop, IDE, CLI/`agy`), normalize the now-fragmented MCP config field conventions across agents, and harden the SoT round-trip.

---

## 1. Background & motivation

Since the previous mcp-synchro baseline (early 2026), the agent landscape shifted in three material ways:

1. **Antigravity split into three products at Google I/O 2026** (May 19, 2026): a brand-new standalone **Antigravity Desktop 2.0** app, the legacy **Antigravity IDE** (the VS Code fork, still maintained), and a new **Antigravity CLI** (`agy`) that replaces the Gemini CLI ([Google I/O 2026 highlights](https://blog.google/innovation-and-ai/technology/developers-tools/google-io-2026-developer-highlights/), [TechCrunch coverage](https://techcrunch.com/2026/05/19/google-launches-antigravity-2-0-with-an-updated-desktop-app-and-cli-tool-at-io-2026/)). Each product reads from its **own** MCP config file, all under `~/.gemini/` ([dev.to: Antigravity is dead, long live Antigravity](https://dev.to/turingsoracle/antigravity-is-dead-long-live-antigravity-186m)).
2. **Gemini CLI sunset is locked in for June 18, 2026** for all tiers (Free, Pro, Ultra). Users will be auto-migrated to `agy`, with a backup snapshot dropped at `~/.gemini/antigravity-backup/` ([TechCrunch](https://techcrunch.com/2026/05/19/google-launches-antigravity-2-0-with-an-updated-desktop-app-and-cli-tool-at-io-2026/)). The existing `gemini` agent definition in `agents.json` must be flagged as deprecated and a migration helper added.
3. **MCP config field conventions diverged further.** The most operationally relevant delta: Antigravity (all three variants) and Windsurf use **`serverUrl`** for remote HTTP, Cursor/VS Code/Claude Code use **`url`**, Gemini CLI uses **`httpUrl`** vs `url` to distinguish transports, and Codex CLI uses TOML with `mcp_servers` (note the underscore, plural section name; `mcp.servers` silently fails) ([Codex config reference](https://developers.openai.com/codex/config-reference), [Gemini CLI MCP docs](https://geminicli.com/docs/tools/mcp-server/), [Composio Antigravity guide](https://composio.dev/content/howto-mcp-antigravity)).

The existing `McpServer` pydantic model already carries `url`, `httpUrl`, `serverUrl`, `headers`, `httpHeaders`, `transport`, `type`, etc. — so this update is mostly *normalization rules* and *new agent definitions* rather than a model rewrite. A handful of footguns (Cursor's `streamable-http` parser bug; Antigravity's 100-tools-per-server hardcoded limit) need explicit guardrails.

---

## 2. Goals (and non-goals)

**Goals:**

- Add native first-class support for Antigravity Desktop 2.0, Antigravity IDE, and Antigravity CLI (`agy`) as three distinct agents in `agents.json`.
- Replace `gemini` agent with a deprecation path → `antigravity-cli`.
- Add per-agent field-convention normalization so a single canonical entry in the SoT writes correctly to every target.
- Add validation guardrails for the two known footguns: Cursor `type: "streamable-http"` silent drop, and Antigravity 100-tool-per-server hard cap.
- Add a per-agent post-write validator (`agy mcp list`, `claude mcp list`, `codex mcp list`) where the CLI exposes one.
- Keep the existing CLI surface (`push`, `pull_new`, `pull_all`, `list`, `show`, `dump`) backward-compatible; add new subcommands behind opt-in flags.

**Non-goals:**

- Project-level / workspace-level config writing for agents that don't natively support it (notably Antigravity — community proxy workarounds exist but are out of scope).
- Server discovery / registry browsing.
- Rewriting the SoT schema. The current `McpServer` model is sufficient.

### 4.1 Normalization rules (writer)

The canonical SoT entry uses `url` + an explicit `transport` field. The writer must, per target:

1. **If `agent.remote_url_key == "serverUrl"`**: rename `url` → `serverUrl` on emit. Strip `httpUrl`. Drop `type` unless the agent's `transport_indicator` is explicit.
2. **If `agent.remote_url_key == "httpUrl"` and transport is `http`/`streamable-http`**: emit as `httpUrl`; for `sse` emit as `url`. (Gemini-style transport-by-key.)
3. **If `agent.name == "cursor"` and transport is `streamable-http` or `http`**: ALWAYS emit `type: "http"`. NEVER emit `type: "streamable-http"` — Cursor's parser silently drops the entire `mcp.json` if any entry has that value ([Cursor forum bug report](https://forum.cursor.com/t/cursor-agent-mcp-list-silently-drops-entire-mcp-json-when-any-entry-has-type-streamable-http-works-in-ide/158521)). Add a unit test for this.
4. **If `agent.name == "codex-cli"`**: emit TOML with `[mcp_servers."<name>"]` section; convert camelCase keys to snake_case (`startupTimeoutMs` → `startup_timeout_ms`); `command` stays a string, `args` is an array.
5. **If `agent.name == "opencode"`**: `command` must be an array (split string commands on shlex); rename `env` → `environment`; inject `enabled: true` and `type: "local"` for stdio servers.
6. **If `agent.name == "crush"`**: emit under `mcp` not `mcpServers`.
7. **If `agent.name == "vscode"`**: nest under `mcp.servers`, not top-level `mcpServers`.

### 4.2 Normalization rules (reader)

Symmetric inverse: when ingesting via `pull_new` / `pull_all`, fold `serverUrl`/`httpUrl` into the canonical `url` + `transport` representation. Preserve `headers` as-is. Reject unrecognized top-level keys with a warning rather than dropping them silently.

## 5. Guardrails & footguns

### 5.1 Antigravity 100-tool-per-server hard cap

Antigravity (all three variants) rejects any MCP server advertising more than 100 tools, with a hardcoded limit that cannot be configured at the user level ([Google AI Developer forum](https://discuss.ai.google.dev/t/critical-dx-issue-antigravity-ide-hardcoded-mcp-tool-limit-100-configuration-fragmentation-with-gemini-cli/143969)).

**Implementation:** when `push` writes to any `antigravity-*` agent, optionally probe each server (`tools/list` via stdio or HTTP) and warn (don't block — the SoT may legitimately span agents) if any server returns >100 tools:

```
⚠ antigravity-desktop: server "atlassian" exposes 187 tools — Antigravity will reject it (hardcoded 100-tool cap).
  Consider splitting the server or using a filtering proxy.
```

Add a `--probe-tools` flag on `push` (off by default — adds latency).

### 5.2 macOS GUI `$PATH` issue (Antigravity IDE & Desktop)

When launched from the Finder/Dock, Antigravity apps inherit only the system `launchd` PATH, not the user shell PATH from `~/.zshrc`. Stdio MCP servers using `npx`/`uvx`/`bunx` then fail with "executable file not found in PATH" ([Google forum bug](https://discuss.ai.google.dev/t/bug-mcp-servers-crash-with-executable-file-not-found-in-path-when-antigravity-is-launched-via-macos-gui/138495)).

**Implementation:** on macOS, when writing to `antigravity-desktop` or `antigravity-ide`, the writer should:

1. Detect commands like `npx`, `uvx`, `bunx`, `python3`, `node` that are likely not in `/usr/bin` or `/usr/local/bin`.
2. Auto-rewrite `command` to the absolute path (`shutil.which(cmd)` resolved against the user's shell PATH, not the agent's).
3. Print a warning suggesting the user launch from terminal (`agy` works fine; only the GUI apps have the bug).

Make this opt-out via `--no-resolve-commands`.

### 5.3 Cursor `streamable-http` silent drop

Already covered in §4.1 rule 3. Add a regression test that fails if any code path emits `type: "streamable-http"` for the `cursor` agent.

### 5.4 Codex CLI `mcp_servers` vs `mcp.servers`

Codex's TOML config uses `[mcp_servers."name"]` (a table with quoted name). A common mistake is `[mcp.servers.name]` which yields a different structure that Codex ignores silently. The writer must always emit the `mcp_servers` form. Add a validator on `pull_new` that warns if it finds an `mcp.servers` table in a user's existing `~/.codex/config.toml` (almost certainly broken).

## 6. Model & module changes

### 6.1 `models.py`

No new fields needed — the existing `McpServer` already has `url`, `httpUrl`, `serverUrl`, `headers`, `httpHeaders`, `transport`, `type`. Add validators:

- `@field_validator("transport")`: accept `stdio`, `http`, `streamable-http`, `sse`, `websocket`; normalize `streamable-http` → `http` for the canonical representation (writer re-expands per agent).
- Cross-field validator: at most one of `url`, `httpUrl`, `serverUrl` may be set in the SoT (canonicalize to `url`).

- Move all per-agent emit logic into a `_normalize_for_agent(server: McpServer, agent: AgentDef) -> dict` helper.
- Implement rules from §4.1 and §5.
- Add `_resolve_commands_for_darwin_gui(server, agent)` for §5.2.

### 6.4 `readers.py`

- Symmetric inverse normalization (§4.2).
- Add Codex TOML parser path: `tomllib.loads()` (stdlib 3.11+).

### 6.5 `sync.py`

- New `push_report` per agent: # servers written, # warnings, # tool-cap violations, validator command output if run.

### 6.6 `cli.py`

New / changed commands:

- `mcp-synchro push [--probe-tools] [--no-resolve-commands] [--validate] [agent1 agent2 ...]`
- `mcp-synchro migrate gemini --to antigravity-cli` — one-shot migration that reads `~/.gemini/settings.json` (legacy) and writes to `~/.gemini/antigravity-cli/mcp_config.json`, then optionally removes the legacy file.
- `mcp-synchro doctor` — runs each agent's `post_write_validate_cmd`, parses output, and reports per-agent health (server count, errors).
- `mcp-synchro agy-sync` — convenience alias that targets `antigravity-desktop`, `antigravity-ide`, and `antigravity-cli` together (the common case after I/O 2026).

## 7. `agy` integration details

The `agy` CLI exposes useful introspection that mcp-synchro can leverage:

- `agy mcp list` — list configured servers and their status; parse for post-write validation.
- `agy mcp add <name> --transport http --url <url>` — could be used instead of file writes for the CLI variant. **Decision:** stick with file writes (file is the source of truth and supports SSE/headers that the CLI add may not); use `agy mcp list` only for read-back verification.
- `agy -p "list mcp servers"` — scripted prompt; usable as a fallback validator.

Reference: [agy hands-on walkthrough](https://dev.to/arindam_1729/antigravity-cli-a-hands-on-guide-to-googles-terminal-coding-agent-5bc7), [Antigravity codelab](https://codelabs.developers.google.com/getting-started-google-antigravity).

## 8. Workspace / project-level configs

The original spec only handled user-global configs. Add explicit handling for the agents that *do* support per-project MCP:

| Agent          | Project file              | Behavior |
|----------------|---------------------------|----------|
| cursor         | `.cursor/mcp.json`        | Merged with global, project wins |
| claude-code    | `.mcp.json` (repo root)   | Merged with `~/.claude.json` |
| vscode         | `.vscode/mcp.json` or `.vscode/settings.json` (`mcp.servers`) | Workspace > user |
| antigravity-*  | **NOT SUPPORTED**         | Print a clear error if `--workspace` is passed |

Add `--workspace PATH` to `push` and `pull_*` to target the project file instead of the global one for the supported agents. Antigravity raises:

```
✗ antigravity-desktop does not support workspace-level MCP config as of May 2026.
  Track https://github.com/google/antigravity/issues for status.
```

## 9. Example configs (reference, per agent)

A canonical SoT entry like:

```json
{
  "name": "atlassian",
  "transport": "http",
  "url": "https://mcp.atlassian.com/v1/sse",
  "headers": { "Authorization": "Bearer ${ATLASSIAN_TOKEN}" }
}
```

renders per agent as:

**antigravity-desktop / antigravity-ide / antigravity-cli** (`~/.gemini/<variant>/mcp_config.json`):
```json
{ "mcpServers": { "atlassian": {
    "serverUrl": "https://mcp.atlassian.com/v1/sse",
    "headers": { "Authorization": "Bearer ${ATLASSIAN_TOKEN}" }
}}}
```

**cursor** (`~/.cursor/mcp.json`):
```json
{ "mcpServers": { "atlassian": {
    "type": "http",
    "url": "https://mcp.atlassian.com/v1/sse",
    "headers": { "Authorization": "Bearer ${ATLASSIAN_TOKEN}" }
}}}
```

**gemini (legacy, deprecated)**:
```json
{ "mcpServers": { "atlassian": {
    "httpUrl": "https://mcp.atlassian.com/v1/sse",
    "headers": { "Authorization": "Bearer ${ATLASSIAN_TOKEN}" }
}}}
```

**codex-cli** (`~/.codex/config.toml`):
```toml
[mcp_servers."atlassian"]
url = "https://mcp.atlassian.com/v1/sse"
startup_timeout_ms = 10000

[mcp_servers."atlassian".headers]
Authorization = "Bearer ${ATLASSIAN_TOKEN}"
```

**opencode** (stdio example, since opencode prefers local):
```json
{ "mcp": { "atlassian-local": {
    "type": "local",
    "command": ["npx", "-y", "@atlassian/mcp-server"],
    "environment": { "ATLASSIAN_TOKEN": "${ATLASSIAN_TOKEN}" },
    "enabled": true
}}}
```

## 12. Open questions

1. **Proxy-based workspace support for Antigravity** — the community is iterating on local MCP proxies that fake workspace-level config by switching the global file on directory change. Should mcp-synchro ship a built-in proxy, or stay out of that hole? Recommend: stay out for 0.4.x; revisit if Google ships native support.
2. **`agy mcp add` vs. file writes** — current spec uses file writes only. If `agy` adds richer fields over time (skill bindings, plugin scopes), revisit.
3. **Should `headers` values be templated through `os.environ`?** The current model leaves `${VAR}` literal in the file. Most agents expand it; opencode does not. Recommend: keep literal, document per-agent expansion behavior in `README.md`.
